# Amén · Wine List

An **installable, offline-readable wine list** for restaurant waiters: the waiter opens the
list of *their* restaurant on a phone or PDA, searches by dish ("oysters") or grape, and gets
the technical sheet and the pairing notes for each bottle.

**What it is:** a front-end demo (PWA) built around a real catalogue of 19 Spanish wines from
Bodegas Andrade and Bodegas Sauci (D.O. Condado de Huelva).
**What it is not:** it is not a shop, not a stock/inventory system, and **it shows no prices
anywhere** — the distributor's prices are B2B and confidential, and each restaurant sells at
its own.

![Wine list, desktop](docs/assets/readme-carta_desktop.png)

## Who it is for

Waiters in restaurant clients of a wine distributor — people who get a 2-hour tasting course
and then forget the names, not sommeliers. The problem it solves is the sale-floor question
*"I'm serving oysters, what do I open?"* answered in one tap, without memorising anything.

**Use case in 5 minutes:** open the URL, type `ostras`, get the one wine whose pairing notes
mention oysters, open its sheet, read the grape, the alcohol and what else it pairs with.

## What it does

- **Catalogue of 19 wines** (8 Bodegas Andrade, 11 Bodegas Sauci), grouped in 7 families:
  blancos, finos, oxidativos secos, dulces, naranja, tinto, vermut.
- **Free-text search** across name, winery, type, grape, pairing and tasting notes, with the
  match highlighted and the query kept in the URL (`/?q=ostras`).
- **Detail sheet**: bottle stage, technical sheet (grape, D.O., alcohol, volume, serving
  temperature), tasting in three blocks (vista · nariz · boca), pairing chips that jump back to
  the search, winery strip with history, and *similar wines* with a criterion.
- **PWA**: installable manifest, service worker, 39 precached entries (bottles, self-hosted
  fonts, CSS, JS) so the list stays readable offline once visited.
- **Data honesty rule**: a field exists only if the source publishes it (winery dossier and
  2026 price list first, official websites additive). Missing data is omitted, never invented;
  documented contradictions are tracked in a separate file, not smoothed over in the UI.

## Requirements

- **Node.js `^20.19.0 || >=22.12.0`** (requirement of Vite 8) and npm 10+. Measured here with
  Node **v24.15.0** / npm **11.9.0** on Windows 11.
- A modern browser (Chromium, Firefox or Safari) — the app is a client-side SPA.
- No backend, no database, no API keys: the catalogue is a typed TypeScript module.

## Quickstart

```bash
# 1. clone
git clone https://github.com/eduardosmulero-tech/vinos-carta-app.git
cd vinos-carta-app

# 2. the app lives in app/
cd app

# 3. install exactly what the lockfile pins
npm ci

# 4. dev server
npm run dev

# 5. open http://localhost:5173/
```

Expected output (Node 24.15.0, npm 11.9.0):

```text
$ npm ci
added 398 packages, and audited 399 packages in 14s
20 vulnerabilities (3 low, 6 moderate, 11 high)   # dev-only toolchain, see Status

$ npm run dev

  VITE v8.1.5  ready in 349 ms

  ➜  Local:   http://localhost:5173/
  ➜  Network: use --host to expose
```

Production build and preview of the built bundle:

```bash
npm run build     # tsc -b && vite build  → dist/ + dist/sw.js + dist/manifest.webmanifest
npm run preview   # serves dist/ on http://localhost:4173/
npm run lint      # oxlint
```

The repository root has its own `package.json` with no scripts: it only holds the QA tools
(`tools/`) — Puppeteer for real renders and WCAG contrast measurement:

```bash
npm ci                       # at the repo root
npm run build --prefix app
npm run preview --prefix app -- --port 4180 --strictPort
node tools/capture-readme.mjs http://localhost:4180
```

## Status

### Measured (commands run on this source tree, 9 Nov 2026)

- `npm ci` in `app/`: **398 packages, 14 s**, lockfile consistent (`app/package-lock.json`).
- `npm run lint` (oxlint): **exit code 0**, no findings.
- `npm run build` (`tsc -b && vite build`): **green** — 45 modules, `dist/assets/index-*.js`
  267.61 kB (85.23 kB gzip), CSS 28.05 kB (6.32 kB gzip), PWA precache **39 entries**
  (1176.27 KiB), `dist/sw.js` + `dist/manifest.webmanifest` generated.
- Dev server: `GET /` → **200**, `/src/main.tsx` → 200, `/logo-amen.jpg` → `image/jpeg`.
- Live deployment: `https://guiasumillerdemo.vercel.app/` answers **200** and serves the
  **same bundle hash** as the local build (`index-BoRrzov8.js`).
- Real renders reviewed by eye at 1280×900 and 390×844 (screenshots above, generated by
  `tools/capture-readme.mjs` from the production build).
- Accessibility: **54 of 54** text/background combinations on the wine sheet (including the
  footer) pass WCAG AA (≥4.5:1) — measured in headless Edge against the production build with a
  Puppeteer script that walks the computed styles and resolves each element's effective
  background. 0 failures. Historical note: the v2 redesign failed 5 of 10 combinations; that
  is documented in `docs/AUDITORIA_UNICA_RETO_V2_2026-07-17.md`.

### Not measured

- Any real restaurant device: the client's PDAs are heterogeneous and **none has been tested**;
  only desktop and phone viewports in headless Edge.
- Lighthouse score, PWA install flow on physical iOS/Android, and offline behaviour under real
  network loss (the service worker is verified by its build artefacts, not by pulling the plug).
- Search quality with a real waiter in front of it — the 19-wine catalogue is a demo size.

### Not implemented

- Admin side: catalogue editing, restaurant onboarding and list assignment (the business model
  is that the distributor manages both).
- Multi-tenant: this is a single, hard-coded list. One restaurant per deployment.
- Login / access codes per restaurant, inventory report, stock.
- Prices in any form (a deliberate product decision, not a missing feature).
- Backend of any kind; data lives in `app/src/data/wines.ts`.
- Languages other than Spanish in the UI.
